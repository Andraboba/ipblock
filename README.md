# ipblock

Фоновый сервис со значком в трее для Windows и macOS: заданные сайты,
IP-адреса и программы доступны только тогда, когда компьютер выходит в сеть
с разрешённого IP. Пример: рабочая почта открывается только из офиса, а из дома
почтовый сервер не получает от компьютера ни одного пакета.

Разрешённые адреса задаются маской, поэтому «плавающий» офисный IP не проблема:

| Запись | Значение |
| --- | --- |
| `203.0.113.17` | один адрес |
| `203.0.113.0/24` | подсеть (CIDR), IPv4 и IPv6 |
| `198.51.100.10-198.51.100.40` | диапазон |
| `192.0.2.*`, `10.1.2?.*` | шаблон по октетам (`*` — что угодно, `?` — одна цифра) |

## Принцип: закрыто, пока не доказано обратное

Всё перечисленное в правилах закрыто всегда. Доступ открывается только на то
время, пока подтверждено, что компьютер выходит в сеть с разрешённого адреса.

- **Запуск, перезагрузка.** Сервис первым делом закрывает всё и лишь потом
  проверяет IP. В Windows правила файрвола сохраняются между перезагрузками,
  поэтому доступ закрыт ещё до старта сервиса.
- **Смена сети** (другой Wi-Fi, кабель, VPN, модем). Система сообщает об этом
  сервису сразу; он закрывает доступ и только после этого перепроверяет IP.
- **Привязка к локальному адресу.** Открытый доступ действует в файрволе только
  для того локального адреса, с которого шла проверка. Если трафик пойдёт через
  другой интерфейс (выдернули кабель — включился Wi-Fi или модем), ядро системы
  его не пропустит само, не дожидаясь сервиса.
- **Сон.** После пробуждения доступ закрывается до перепроверки.
- **IP не определяется.** Доступ закрыт.
- **Остановка сервиса.** Доступ закрывается полностью (`on_stop: lock`).
- **IPv4 и IPv6 проверяются отдельно.** Если в `allow_from` только IPv4,
  по IPv6 к закрытым адресам доступа нет никогда.
- **Адреса сайтов** сервис узнаёт только пока доступ открыт. С чужого адреса
  он к их DNS не обращается.

| Что закрывается | Чем |
| --- | --- |
| Адреса серверов (`ips`) | файрвол в ядре: Брандмауэр Windows / `pf` в macOS |
| Программы (`apps`) | Windows — запрет сети программе в файрволе; `action: kill` вдобавок закрывает её. macOS — только закрытие программы |
| Сайты (`domains`) | запись в `hosts` плюс файрвол по запомненным IP сайта |

Какой IP сравнивается, задаёт `ip_source`:

- `public` — внешний адрес, под которым вас видит интернет (подходит для «я в офисе»);
- `local` — адрес сетевой карты или Wi-Fi внутри сети (например `10.20.x.x`);
- `any` — достаточно совпадения любого из них.

## VPN

Доступ открывается и через VPN, если с ним компьютер выходит в сеть с разрешённого адреса.

- **VPN пускает через себя весь трафик.** Внешний IP становится адресом VPN.
  Если он подходит под `allow_from`, доступ открывается через несколько секунд
  после подключения — ничего настраивать не нужно. Открытый доступ привязан к
  адресу VPN-адаптера, поэтому при обрыве VPN трафик не пойдёт напрямую:
  ядро закроет его сразу.
- **VPN пускает через себя только рабочие адреса** (раздельное туннелирование).
  Внешний IP для остального интернета остаётся домашним, и правило по `public`
  не сработает. Укажите подсеть, из которой VPN выдаёт адрес вашему компьютеру:

  ```yaml
  ip_source: any            # внешний IP офиса ИЛИ адрес VPN-адаптера
  allow_from:
    - 203.0.113.0/24        # офис
    - 10.8.0.0/24           # адреса, которые выдаёт рабочий VPN
  ```

  Тогда доступ к закрытым адресам возможен только с адреса VPN-адаптера,
  то есть только через туннель.

- **VPN ведёт трафик к разным сайтам через разные серверы.** Тогда сервисы,
  у которых ipblock спрашивает внешний IP, видят разные адреса. Сервис опрашивает
  их все сразу при каждой проверке, а `ipblock check`, `status` и панель
  показывают, какой сервис какой адрес видит.

  Правило открывается, только если разрешены **все** увиденные адреса: неизвестно,
  каким из серверов VPN воспользуется защищаемый сайт. Если нужен только один из
  адресов, укажите в правиле сервисы проверки, которые идут тем же путём, что и
  защищаемый сайт (лучше два — на случай, если один не ответит):

  ```yaml
  allow_from:
    - 203.0.113.17
  ip_services:
    - https://icanhazip.com
    - https://1.1.1.1/cdn-cgi/trace
  ```

  Какой сервис подходит, зависит от правил вашего VPN; это ваше решение, программа
  проверить его не может. В панели это раздел правила «Если VPN ведёт разные сайты
  через разные серверы».

Включение и выключение VPN считается сменой сети: доступ сначала закрывается,
затем перепроверяется.

## Чего программа гарантировать не может

Прочитайте этот раздел, если требование «ни одного пакета с чужого адреса» для вас жёсткое.

- **Внешний IP сменился, а на компьютере ничего не изменилось** (провайдер
  офиса выдал другой адрес, роутер переключился на резервный канал). Компьютер
  об этом не узнаёт; это замечает только очередная проверка, то есть в пределах
  `check_interval` (по умолчанию 20 секунд, минимум 5). До неё пакеты могут
  уйти с нового адреса.
- **Сайты, заданные только именем.** Надёжно закрыты те IP сайта, которые
  сервис успел запомнить, пока доступ был открыт. Если сайт отдаст новый адрес,
  а программа узнает его в обход `hosts` (собственный DNS, DoH), пакет уйдёт.
  Для жёсткой защиты укажите подсети сервера в `ips`.
- **Программы на macOS.** Запретить сеть отдельной программе там нельзя.
  Программа закрывается примерно за секунду после запуска, и за это время может
  успеть выйти в сеть. На Mac обязательно перечислите `domains` и `ips` её серверов.
- **Прокси.** Если программа ходит через прокси-сервер, файрвол видит адрес
  прокси, а не сервера. В Windows запрет сети программе действует и в этом случае.
- **Приложения из Microsoft Store и на WebView2.** Сеть у них может идти через
  другой процесс. Укажите папку программы (закроются все `.exe` в ней) и её
  серверы в `ips`.
- **Выключенный Брандмауэр Windows.** Правила не действуют в том профиле сети,
  где он выключен. Сервис предупреждает об этом в `check`, `status` и в значке.
- **Администратор.** Кто имеет права администратора на компьютере, может
  остановить сервис и снять блокировки.

## Значок

После установки в области уведомлений (Windows) или в строке меню (macOS)
появляется значок и запускается при каждом входе в систему:

| Значок | Значение |
| --- | --- |
| зелёный с галочкой | доступ открыт по всем правилам |
| красный с полосой | доступ закрыт |
| оранжевый с «!» | открыта часть правил либо есть проблема (например, выключен файрвол) |
| серый с точками | сервис не работает |

В меню — текущий внешний IP, состояние каждого правила, «Панель управления…», «Файл настроек…» и «Журнал».
«Убрать значок» закрывает только значок: сервис продолжает работать.
Значок ничего не блокирует сам, он показывает решения сервиса.

## Панель управления

Панель открывается в браузере из меню значка («Панель управления…») или командой
`ipblock ui`. Через неё можно делать всё то же, что и правкой файла настроек:

- добавлять, изменять и удалять правила — название, какой IP сравнивать, разрешённые
  адреса, сайты, адреса серверов, программы;
- менять общие настройки — интервал проверки, поведение при остановке сервиса,
  файл журнала, сервисы определения внешнего IP.

Файл по-прежнему можно править и вручную: панель и файл — два входа к одним и тем же
настройкам. При сохранении панель проверяет их так же, как сервис при чтении, и
неверное значение не записывает. Если файл тем временем изменили другим способом,
панель об этом скажет и не перезапишет чужую правку.

Поиск адресов программы:

1. Выберите программу из списка запущенных (сверху те, что сейчас соединены с сетью).
2. Поработайте в ней как обычно. Панель показывает адреса, к которым программа
   обращается, порты и, где известно, имя сайта.
3. Отметьте нужные адреса и нажмите «Добавить в настройки»: адреса и сама программа
   записываются в выбранное или новое правило. Можно добавлять подсетями `/24`.

Что стоит знать:

- Панель работает только на этом компьютере и только пока открыта. Каждый запуск
  получает случайный ключ в ссылке; без него сервер не отвечает.
- В Windows панели нужны права администратора (система спросит разрешение):
  без них настройки не сохранить.
- Видны TCP-соединения. Адреса, к которым программа обращается только по UDP,
  в список не попадают; обычно это те же серверы.
- Наблюдайте, пока доступ открыт: закрытая программа ни с кем не соединяется.
- Имена сайтов берутся из системного кеша DNS Windows, в сеть для этого ничего
  не уходит. В macOS адреса показываются без имён.
- У крупных сервисов адресов много, и они меняются. Найденный список — это то,
  к чему программа обращалась, пока вы наблюдали, а не все её серверы.
- При сохранении комментарии в файле настроек остаются, прежняя версия
  сохраняется рядом как `config.yaml.bak`.

## Сборка

Нужен Go 1.26 или новее.

Windows:

```bash
go build -o dist/ipblock.exe ./cmd/ipblock
```

```bash
go build -ldflags "-H=windowsgui" -o dist/ipblock-tray.exe ./cmd/ipblock-tray
```

macOS — собирать на самом Mac (нужны Xcode Command Line Tools: `xcode-select --install`),
потому что значок использует системные библиотеки:

```bash
go build -o dist/ipblock ./cmd/ipblock
```

```bash
go build -o dist/ipblock-tray ./cmd/ipblock-tray
```

Сервис для Mac без значка можно собрать и на Windows:
`GOOS=darwin GOARCH=arm64 go build -o dist/mac-arm64/ipblock ./cmd/ipblock`.

## Установка

Windows — в терминале, открытом «от имени администратора»; macOS — через `sudo`.
`ipblock` и `ipblock-tray` должны лежать в одной папке.

1. Проверить, что блокировка на этой машине действительно работает: `ipblock selftest`
2. Создать пример настроек: `ipblock init`
3. Отредактировать файл:
   - Windows: `C:\ProgramData\ipblock\config.yaml`
   - macOS: `/Library/Application Support/ipblock/config.yaml`
4. Посмотреть, как правила сработают сейчас: `ipblock check`
   (ничего не меняет в системе, права администратора не нужны)
5. Установить сервис и значок с автозапуском: `ipblock install`

Файл настроек перечитывается сам при следующей проверке, перезапуск не нужен.

## Команды

| Команда | Что делает |
| --- | --- |
| `ipblock selftest` | на проверочном адресе убеждается, что файрвол закрывает соединения и привязка к локальному адресу работает. Если включены две сети сразу (VPN и Wi-Fi), проверяет главный случай: доступ открыт для одной — через другую не проходит ни одно соединение. Рабочие правила не трогает |
| `ipblock init` | создаёт пример настроек |
| `ipblock check` | показывает текущие IP и решение по каждому правилу |
| `ipblock run` | работает в текущем окне до Ctrl+C (удобно для пробы) |
| `ipblock install` | ставит сервис и значок с автозапуском и запускает их |
| `ipblock status` | результат последней проверки сервиса |
| `ipblock ui` | открывает панель управления в браузере |
| `ipblock start` / `stop` | запуск и остановка сервиса |
| `ipblock clear` | снимает все блокировки |
| `ipblock uninstall` | удаляет сервис и значок, снимает блокировки |

Любой команде можно указать другой файл: `ipblock check -config путь\к\config.yaml`.

Журнал лежит рядом с настройками (`ipblock.log`): в него пишутся только смены
решения и ошибки. Там же `status.json` (последняя проверка) и `learned.json`
(запомненные IP сайтов).

## Настройки

Полный пример с комментариями — [internal/config/example.yaml](internal/config/example.yaml).

```yaml
check_interval: 20s
on_stop: lock          # lock — при остановке сервиса доступ закрыт; clear — блокировки снимаются

rules:
  - name: рабочая почта
    ip_source: public
    allow_from:
      - 203.0.113.0/24
    domains:
      - mail.example.com
    ips:
      - 192.0.2.0/24   # подсеть почтового сервера — самая надёжная защита
    apps:
      - windows: 'C:\Program Files\Microsoft Office\root\Office16\OUTLOOK.EXE'
        darwin: /Applications/Microsoft Outlook.app
        action: kill
```

## Прочее

- **Поддомены.** Файл `hosts` не понимает `*.example.com` — каждый поддомен
  указывается отдельной строкой.
- **Общие адреса (CDN).** Запомненные IP сайта могут принадлежать и другим
  сайтам; вне офиса они тоже будут закрыты. Отключается: `resolve_domains: false`.
- **VPN.** Внешний IP определяется таким, каким его видит интернет. При
  включённом VPN это адрес VPN; включение и выключение VPN считается сменой сети.
